# 低盤面の移動生成の省略実験

2026-11-07、Hikari Rust `3310037` を基準に実装・測定しました。両機能とも既定では無効です。

- `fast-low-stack`: 高さ16未満で、空中の左右移動・回転経路を種類ごとに事前計算し、着地した状態から従来の探索を続けます。
- `prune-low-stack`: 上記に加え、地形の上へ戻るスピンなしの状態の再展開を省略します。cold-clear の ZeroG fast mode を参考にした近似処理で、移植コードそのものではありません。
- 高さ16以上は従来のMiraiを使います。探索・評価・ノード上限は共通で、Board本体に列高を保持させる変更は入れていません。

参考: [cold-clear の低盤面向け移動生成](https://github.com/MinusKelvin/cold-clear/blob/279edd7c3177ff8077f6a930193397814b281f27/libtetris/src/moves.rs#L63)。

## 測定方法

macOS arm64、Rust 1.99.0、release/LTO。移動生成は同一の313盤面×7種類を比較しました。決定論的に合法配置から作った96盤面、特殊形状24盤面、空盤面1件、既存の自己対局96盤面、実時間Ultra96盤面です。正式評価用seedと対戦相手内部は使っていません。

配置は物理セルとT-spin状態で比較し、代表回転・操作コスト・列挙順の差も記録しました。出力された全配置について、操作経路を再生し入力コストを独立に計算しています。

単体測定はウォームアップ後、盤面の高さ別に全ケースを均等に反復し、AB/BAを交互に5ペア測定しました。表の値は同じペアの「元版の所要時間÷実験版の所要時間」の中央値です。

探索は1回3秒、1/4ワーカー、batch=128、max_depth=32、上限3200万ノード。同じ盤面・seedをAB/BA順で3ペア測定しました。公開開発seedは41001〜41003です。72実行すべて3秒を完走し、死亡・ノード上限到達はありません。

## 探索全体

値は、実測秒数で割った保持ノード数を同じseed同士で比較した倍率の中央値です。括弧内は3ペアの最小〜最大です。中央値どうしのノード数を割った値とは一致しない場合があります。

| 初期盤面 | ワーカー | 事前計算のみ | 事前計算＋枝刈り |
| --- | ---: | ---: | ---: |
| 空 | 1 | 1.047倍（0.991〜1.083） | 1.135倍（1.067〜1.166） |
| 空 | 4 | 0.986倍（0.965〜1.028） | 1.071倍（1.016〜1.095） |
| お邪魔4行 | 1 | 1.060倍（1.029〜1.094） | 1.121倍（1.116〜1.131） |
| お邪魔4行 | 4 | 0.999倍（0.985〜1.050） | 1.048倍（1.040〜1.050） |
| お邪魔9行 | 1 | 1.058倍（1.042〜1.091） | 未測定 |
| お邪魔9行 | 4 | 1.009倍（0.894〜1.040） | 未測定 |
| お邪魔17行 | 1 | 0.976倍（0.964〜1.017） | 未測定 |
| お邪魔17行 | 4 | 0.976倍（0.930〜1.000） | 未測定 |

事前計算のみでは、低〜中盤面の1ワーカーで約5〜6%増、4ワーカーではほぼ横ばいでした。追加の枝刈り込みでは、空/お邪魔4行で1ワーカー約12〜14%増、4ワーカー約5〜7%増でした。空盤面4ワーカーの保持ノード数の中央値は5,492,035→5,879,927です。強い版のお邪魔9/17行の探索全体は未測定です。

高い初期盤面でも、子孫で低くなれば最適化が働きます。従って、お邪魔17行からの探索全体を「最適化が完全に無効な対照」とは扱いません。

## 配置・経路の差

元版の51,743候補に対し、事前計算のみでは配置欠落・追加ともに0でした。ただし操作コストは1,493候補で変化（1,481候補が+1、12候補が-1）し、589ケースで列挙順/生の候補列も変わりました。初期状態の登録順が変わるため、原典と完全に同じ結果を保つ処理ではありません。

枝刈り込みでは25配置を失いました（J通常1、L通常1、T通常22、Tミニ1）。うちUltraの実プレイ盤面で6配置が欠落しました。確認した範囲でFull T-spinの欠落はありませんでしたが、他の盤面での完全性を保証するものではありません。

全版で出力経路の再生/コスト検証エラーは0でした。16行以上では配置・コスト・列挙順が全件一致しました。候補数やコスト・順序が変わるため、探索ノード数の増加を勝率改善とは扱いません。プレイの強さは未測定です。

## 実装と再現

`src/movegen.rs` に実験実装、`examples/movegen_probe.rs` に配置比較と単体測定、`tools/benchmark_low_stack.py` にペア測定があります。

```sh
# 事前計算のみ
cargo build --release --offline --features fast-low-stack
# 事前計算＋近似枝刈り
cargo build --release --offline --features prune-low-stack
# 既定の原典移植へ戻す
cargo build --release --offline
```

実行バイナリ・入力盤面・公開seed・全コマンド・ハッシュ・生の測定値は `runs/experiments/low-stack-movegen-v1/` に保存しました。`results/` が事前計算のみ、`pruned-results/` が追加枝刈り込みです。1ペアずつ直列に実行し、測定中は他のビルドやベンチマークを走らせていません。

追加テストはキャッシュ経路、入力コスト、高さ境界での従来処理との一致、接地後操作の再生、T-spin経路を確認します。既定版50テスト、事前計算版53テスト、枝刈り版54テストが成功しました。全機能のClippy（警告をエラー扱い）と整形検査も成功しています。
